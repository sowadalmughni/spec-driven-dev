# Atomic Prompt Structure

Every implementation prompt generated by this skill follows this exact structure. Deviation is not permitted.

An atomic prompt has one responsibility. If it cannot be verified with a bash command that returns exit code 0 or 1, it is not atomic enough. Break it down.

---

## Template

```
## SKILL
[One sentence: what this prompt implements. Must be traceable to a task in the Feature Spec.]
Architecture reference: ./docs/architecture-[feature-name].md § [section name]
Spec reference: ./docs/feature-spec-[feature-name].md § [component name]

## DEPENDS
- Task [N] must complete successfully before this task begins
- Reason: [why — shared schema, interface contract, etc.]
- [If no dependencies: DEPENDS: none — this task can begin immediately]

## TASKS
1. Create `./src/[path/to/file.ts]`
   - [Exactly what this file contains: class name, methods, imports]
   - [No additional responsibilities beyond what is listed]

2. Modify `./src/[path/to/existing-file.ts]`
   - Add: [method name and signature]
   - Do NOT modify: [existing methods — list them]

3. Add migration `./src/database/migrations/[timestamp]-[description].ts`
   - Schema: [table name, columns, indexes, RLS policy]

[Each task references an exact file path. No ambiguous "add a service" instructions.]

## VERIFY
```bash
# Task 1: File exists and compiles
test -f ./src/[path/to/file.ts] && echo "PASS: file exists" || echo "FAIL: file missing"
npx tsc --noEmit && echo "PASS: TypeScript compiles" || echo "FAIL: compile error"

# Task 2: New method is present
grep -n "[method-name]" ./src/[path/to/existing-file.ts] && echo "PASS: method found" || echo "FAIL: method missing"

# Task 3: Migration file exists and has RLS policy
test -f ./src/database/migrations/[timestamp]-[description].ts && echo "PASS: migration exists" || echo "FAIL: migration missing"
grep -n "ROW LEVEL SECURITY" ./src/database/migrations/[timestamp]-[description].ts && echo "PASS: RLS present" || echo "FAIL: RLS missing — STOP"

# Integration test (if applicable)
npm run test -- --testPathPattern=[feature-name] && echo "PASS: tests pass" || echo "FAIL: tests failing"
```

## PASS-FAIL
PASS criteria (all must be true):
- [ ] All VERIFY commands return exit code 0
- [ ] No TypeScript errors
- [ ] No new lint errors introduced
- [ ] Test coverage for new code: ≥ [80]%

FAIL criteria (any triggers a stop):
- TypeScript compile error
- Missing RLS policy on any new table
- Credentials found in source files
- N+1 query without documented mitigation

## REPORT
On completion, output:
- Files created: [list with line counts]
- Files modified: [list with change summary]
- VERIFY results: [paste terminal output]
- Open issues: [anything deferred, anything unclear]

## COMMIT
```
git add [exact files]
git commit -m "[feat|fix|schema|security]: [feature-name] — [task description]

- [File 1]: [what changed]
- [File 2]: [what changed]

Spec: docs/architecture-[feature-name].md
Task: [N] of [total]"
```
```

## Anti-Patterns: Prompts That Are Not Atomic

These are failure modes. If a prompt contains any of the following, it must be split.

| Anti-Pattern | Problem | Fix |
|-------------|---------|-----|
| "Build the authentication flow" | Multiple files, multiple responsibilities, cannot be verified in one command | Split into: auth middleware, token validation, session creation, refresh logic — each as separate tasks |
| "Set up the database" | Schema + migration + seed + indexes + RLS = at least 4 atomic tasks | One task per schema change, one per index, one for RLS policies |
| "Wire up the frontend to the backend" | Ambiguous. What route? What component? What state change? | Specify the exact component, the exact API call, the exact state update |
| "Add error handling" | Error handling for what? Which errors? At which layer? | Specify: controller-level 400s, service-level business exceptions, repository-level constraint violations — separately |
| "Implement the user profile feature" | This is a PRD, not a task | This requires a Feature Spec and Architecture before any tasks exist |

## Example: Correct Atomic Prompt

```
## SKILL
Create the UserRepository class that handles all database operations for the users table.
Architecture reference: ./docs/architecture-user-profiles.md § Data Layer
Spec reference: ./docs/feature-spec-user-profiles.md § UserRepository

## DEPENDS
- Task 1 (database migration for users table) must complete successfully
- Reason: UserRepository imports the User entity which depends on the migrated schema

## TASKS
1. Create `./src/modules/users/users.repository.ts`
   - Export class UserRepository with constructor injecting DataSource
   - Implement: findById(id: string): Promise<User | null>
   - Implement: findByEmail(email: string): Promise<User | null>
   - Implement: create(dto: CreateUserDto): Promise<User>
   - Implement: update(id: string, dto: UpdateUserDto): Promise<User>
   - All queries use parameterized statements. No string interpolation.
   - No business logic in this class — data access only.

## VERIFY
```bash
test -f ./src/modules/users/users.repository.ts && echo "PASS" || echo "FAIL"
grep -n "findById\|findByEmail\|create\|update" ./src/modules/users/users.repository.ts | wc -l | xargs -I{} sh -c '[ {} -ge 4 ] && echo "PASS: all methods present" || echo "FAIL: methods missing"'
npx tsc --noEmit && echo "PASS: compiles" || echo "FAIL: compile error"
npm run test -- --testPathPattern=users.repository && echo "PASS: tests pass" || echo "FAIL: tests failing"
```

## PASS-FAIL
PASS: All 4 methods exist, TypeScript compiles, tests pass.
FAIL: Any string concatenation in queries — stop and rewrite with parameterized queries.

## REPORT
Files created: users.repository.ts ([line count] lines)
VERIFY: [paste output]

## COMMIT
```
git add src/modules/users/users.repository.ts
git commit -m "feat: user-profiles — UserRepository with parameterized CRUD

- users.repository.ts: findById, findByEmail, create, update
- All queries parameterized — no string interpolation
- No business logic — data access layer only

Spec: docs/architecture-user-profiles.md § Data Layer
Task: 2 of 8"
```
